# 생태계 탐사와 개인 엽서 — GitHub / Vercel

## 이번 수업 흐름
1. 교사가 수업을 만들고 6모둠에 생태계(숲·바다·강·어항·화단·연못)를 지정합니다.
2. 학생들은 공통 링크에서 자기 모둠을 선택합니다. 수업 코드를 입력하지 않습니다.
3. 모둠별로 같은 사진을 관찰하며 무엇이 보이는지 말합니다. 공동 기록란에 관찰한 내용을 적고 ‘모둠 기록 저장’을 누릅니다. 약 2초마다 모둠원과 교사 화면에 공유됩니다. 입력 도중에는 공유되지 않습니다.
4. 한 명이 모둠 결과를 제출합니다. 교사는 사진과 관찰 기록을 나란히 띄워 간단히 발표하게 합니다.
5. 학생은 ‘개인 엽서 만들기’를 누릅니다. 모둠이 조사한 곳과 관계없이 6개 생태계에서 원하는 곳을 선택합니다.
6. 동물이 되어 사는 곳을 소개하는 글을 쓰고, 테두리·스티커로 꾸민 뒤 PNG로 저장합니다.

모둠 기록은 Firebase에 공유됩니다. 개인 엽서는 서버에 보내지 않으며 각 브라우저에 따로 자동 보관됩니다. 기기·브라우저를 바꾸면 개인 엽서가 따라가지 않습니다. 한 기기를 다음 학생이 쓰는 경우 ‘내 엽서 새로 만들기’를 누릅니다. 개인 엽서의 생태계를 바꾸어도 모둠 기록은 바뀌지 않습니다.

## 기존 배포 업데이트
GitHub의 app/page.tsx, app/globals.css, app/layout.tsx, app/api/classroom/route.ts를 교체하고 app/PersonalPostcard.tsx를 추가합니다. Vercel에 다시 배포합니다. Firebase 프로젝트와 FIREBASE_SERVICE_ACCOUNT 환경 변수, Firestore 규칙은 그대로 유지합니다. 기존 수업을 재사용할 수 있습니다. 기존 공동 엽서의 소개 글은 모둠 기록으로 남으므로 수업을 새로 시작하려면 교사가 새 수업을 만듭니다. 기존 제출 자료가 잠겨 있으면 ‘기록 수정 허용’을 누르고 관찰 단계로 전환합니다.

## 처음 배포
1. 이 폴더 안의 파일과 app, public 폴더를 GitHub 저장소에 올립니다.
2. Firebase 프로젝트에서 Cloud Firestore 데이터베이스를 만듭니다. Standard, (default), 프로덕션 모드로 생성합니다.
3. Firebase 프로젝트 설정 → 서비스 계정에서 비공개 키 JSON을 생성합니다. 이 키 파일을 GitHub에 올리지 않습니다.
4. Vercel에서 GitHub 저장소를 가져옵니다. Framework Preset은 Next.js입니다.
5. 환경 변수 FIREBASE_SERVICE_ACCOUNT에 서비스 계정 JSON 전체 내용을 넣습니다. NEXT_PUBLIC_ 접두사를 붙이지 않습니다.
6. 배포한 다음 교사 화면에서 새 수업을 만듭니다.

firestore.rules는 브라우저 직접 읽기·쓰기를 차단하며 서버 Admin SDK가 데이터를 처리합니다. 학생 이름은 모둠 입장에 필요하지 않습니다. 교사 권한은 수업 생성 브라우저에 보관됩니다. 새 수업을 만들면 학생 입장 화면이 최신 수업에 연결됩니다. 이미 입장한 학생은 기존 수업에 남습니다.

개인 엽서만 사용하려면 배포 주소에 /?mode=personal을 붙여 바로 열 수 있습니다. 개인 활동에는 Firebase 연결이나 모둠 입장이 필요하지 않습니다.
